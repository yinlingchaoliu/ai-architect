# S11 · 整体验证与试运行交付

状态：planned。前置：S10。对应目标：全层集成。依据：[原验收矩阵](../ai-archtect/06-project-roadmap.md#5-验收矩阵)和 S01–S10 的实际交付文档。

## 1. 目标

验证新架构从接入、注册配置、四模式、运行内核、A2A/资源到存储观测的完整链路，并交付可回滚的试运行候选。先验收真实内部集成，再验收获准的外部模型/工具和业务质量；生产发布是否进行，以当时明确任务范围和环境为准。

## 2. 验证工作包

| ID | 工作包 | 必需场景与证据 |
|---|---|---|
| S11-A | 可重现环境与端到端 | 干净锁安装、API/Worker/DB/工件存储联通，完整用户场景和实际制品版本 |
| S11-B | 注册/配置一致性 | 动态注册、并发发布、实例过期、缓存漏事件、授权撤销、回滚后新旧 Run |
| S11-C | 四模式与 A2A | 各模式成功/失败/等待/停止；独立 SDK 对端，断流、重复提交、远端未知结果 |
| S11-D | 故障与恢复 | API/Scheduler/Worker 重启、队列重复、DB 断连、工具已执行后落库失败、checkpoint 不兼容 |
| S11-E | 安全与隔离 | 租户/会话/对象/事件越权，secret 脱敏，出站和代码/文件工具边界 |
| S11-F | 容量与质量成本 | 固定数据/模型/工具/预算，分开管理开销、模型等待、端到端；与单 Agent/旧图比较 |
| S11-G | 部署和回滚演练 | API/Worker 启停、数据库迁移、在途任务处理、工件恢复、告警和值班交接 |

每个工作包都固定输入、命令、环境、候选 hash、实际回执和失败记录。使用 mock 只能证明相应机制；真实内部服务、远端 A2A、外部模型、生产环境的验证边界分别说明。

把[LC-F01–LC-F10 特性矩阵](01-langchain-upgrade.md#3-必须采用和验证的能力)纳入整体复核：检查 create_agent、middleware、结构化输出、context、v3 流、内置 MCP 和持久恢复实际进入对应链路。beta 项记录精确版本、启用范围、测试和关闭路径，不因主包稳定便自动标为已通过。

## 3. 交付和退出条件

- S01–S10 的关键文档已补齐实施与验证，不再只有 planned 内容；每个支持中的模块和能力均有准确去向。
- 必需功能、数据隔离、重复副作用控制、取消与恢复、四模式终止规则和独立 A2A 互通通过；未知结果可见且有处理责任。
- 在 S02 固定的业务用例、质量与容量门槛下给出实测结论；不因测试数量多或运行结束就宣布接受。
- 交付 API/Worker 制品、精确锁/镜像 digest、配置/Schema 版本、数据库迁移、Dashboard/告警、操作手册、备份恢复、回滚和已知限制。
- 产品/业务对输出接受、运行工程交付、试运行部署结果分别记录。没有生产证据时只标试运行候选。

## 4. 灰度和回滚

按测试租户 → 少量新 Run → 扩大范围推进；每批检查失败/未知结果、副作用、延迟、成本和数据隔离。具体阈值用 S02 冻结的数值和 S11 测量结果，不在本计划虚构承诺。

触发回滚时先停新派发，再排空/取消和对账在途任务，切回兼容制品/配置；保留事件、工件和远端映射。数据变更采用兼容新增/回填/切换/后续清理，不把代码回滚当成外部动作撤回。恢复后必须检查实际状态和用户可见结果。

## 5. 本阶段重要文档与最终交接

本篇作为整体验证主文档，包含候选架构图、版本清单、逐项验收结果、质量/成本/容量报告、故障/回滚实录、业务接受和运维交接。必要的测试日志和部署手册作为明确链接附件；不得用附件存在替代结论。

当前端到端、故障、外部调用、压测、试运行和业务验收均为 **not_run**。本目录计划编写完成与平台改造完成分开记录。
