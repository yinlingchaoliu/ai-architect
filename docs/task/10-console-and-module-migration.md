# S10 · 应用入口与存量模块迁移

状态：planned。前置：S09。对应目标：L1、L5。依据：[模块迁移建议](../ai-archtect/06-project-roadmap.md#4-现有模块如何迁移)。

## 1. 目标与入口变化

让用户经平台 API 管理 Agent、发布配置、运行四种模式并查看状态/工件，把剩余有使用价值的样例逐项接入或明确保留为独立示例。原有 Streamlit 可先作为独立 API 客户端复用；是否重写为其他前端在本步固定，不把新框架选型作为已实现结果。

```text
用户 → 管理台 / Chat → 平台 API → Registry / Runtime → Adapter → 能力
                          ← 持久事件 / owner / 产物与来源
```

前端不直接取得供应商密钥，不绕过平台调用模型/工具；多模态文件经工件接口上传、授权和引用。

Agent Adapter 优先消费 v3 Event Streaming 的消息、工具和子图投影，平台落成自己的版本化事件再供 UI 查询/订阅。标准 content_blocks 保留文本/多模态/引用的类型；UI 不解析 provider 私有块或依赖旧 stream tuple 形状。新平台主路径采用内置 MCPAdapter，S01 遗留 adapters 兼容环境在本步逐项退出。[当前特性基线](01-langchain-upgrade.md)

## 2. 实施任务与模块去向

| ID | 范围 | 改造和交付（拟） | 验收重点 |
|---|---|---|---|
| S10-A | Agent/配置管理 | 目录、健康、revision diff、发布、回滚、排空 | 展示 desired/observed，按权限操作 |
| S10-B | Run/Chat | 选择 Workflow、提交、SSE、续答、取消、工件 | 断线补读，不把未知外部动作显示为已停止 |
| S10-C | 四模式过程视图 | DAG、Supervisor 决策、Handoff owner、Swarm 任务板 | 来源是持久事件，界面不生成执行事实 |
| S10-D | `server` / WebUI | 保留兼容接口或明确退役；页面改走平台 API | 原客户端兼容、错误和流语义可回归 |
| S10-E | 会议/旅行/Manus | 清理已替代控制逻辑，保留专业能力和对照样例 | 默认入口只走一个 Runtime，失败语义一致 |
| S10-F | RAG/CSV/公共库 | 真实检索/SQL 只读 Adapter 或独立服务；公共库按需复用 | 来源/索引版本、租户权限、受限 SQL；不整体导入旧依赖 |
| S10-G | MCP 和遗留兼容层 | 工具全部绑定；逐项处理 S01 classic/experimental 保留项 | 有迁移结论和支持边界，不留无期限例外 |

每个模块必须在清单中归为“已迁移并验证”“独立示例，不进入平台默认链路”“有期限兼容”“待移除”。默认平台链路不再直接使用旧 AgentExecutor/旧 SessionManager 来重复调度；community 的传递 classic 依赖不等同于业务还在用旧编排。

## 3. 验收与回滚

用户流程覆盖注册发布 → 发起四模式 → 等待/续答 → 转交/任务板 → 产物 → 取消/回滚，检查并发会话隔离和越权。对每个迁移模块记录旧入口和新入口的行为差异；新增真实搜索/RAG 不得使用模拟来源冒充真实证据。

关闭旧入口前盘点使用者、兼容 API、历史记录和在途任务。分批切换新请求，旧任务排空；有副作用任务不双写/双执行。回滚撤销新流量分配，保留新平台数据和工件，对账后恢复获准的旧入口；不回滚到无法读取当前数据的旧程序。
