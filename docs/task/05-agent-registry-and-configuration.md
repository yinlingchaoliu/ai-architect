# S05 · 注册中心与配置治理

状态：planned。前置：S04。对应目标：L2。设计依据：[动态注册与配置](../ai-archtect/02-agent-registry-and-configuration.md)。

## 1. 目标与架构变化

把构造函数中的固定 Agent 字典、Python 配置和启动时路由装配，升级为持久定义目录、健康实例发现和可审计的版本发布。新请求不再自行扫描文件或在每轮跟随 latest。

```text
管理 API → 定义/配置校验 → 不可变 revision → CAS 发布指针
实例注册/健康观察 → Discovery 资格过滤 → Runtime 固定参与者版本后派发
```

## 3. 配置生效规则

Prompt、模型、工具和能力 Schema 的修改通过新 revision 作用于新任务；已运行任务继续固定版本，显式迁移另记录。授权撤销、密钥吊销、禁用和必要的运行限额收紧对后续调用立即生效，不能被历史快照绕过。

默认配置合并仅覆盖 Schema 允许的字段，secret 只保留引用。新插件代码经构建和允许制品部署，注册 API 不接受任意 import 路径、脚本或 pip 安装。运行中新增托管实例无需重启 API；发布新本地实现可能需要 Worker 部署，必须如实区分。

## 4. 验收与回滚

运行中注册一个新能力实例并发现、调用；并发发布只有一个 CAS 成功；旧 Run 的配置 hash 不随发布变化；租约过期停止新派发；禁用阻止后续动作；删除不破坏历史。测试跨租户目录读取、配置引用越权、缺失制品和控制面不可用。

回滚切回已验证的发布指针，不改历史定义；下线新实例先排空并核对在途任务。数据表保留向后兼容的新增字段，不能回滚代码后丢失配置来源。
