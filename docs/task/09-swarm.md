# S09 · Swarm 协作与收敛

状态：planned。前置：S08。对应目标：L3、L4。依据：[Swarm 设计](../ai-archtect/04-collaboration-patterns.md#5-swarm)。

## 1. 目标与模式语义

实现有边界的共享任务板 Swarm：多个已注册 Agent 在同一目标下自主提出工作、认领任务、请求协助、提交和交叉审阅。Runtime 只保障一致性、权限和硬限制；不替所有 Agent 作每一步业务选择，也不把一次 gather 称为 Swarm。

```text
共享目标/任务板 ↔ Agent A / B / C 的独立决策
               → 原子认领 → 独立执行/产物 → 交叉审阅/版本化合并
               → 完成规则满足，或硬限制停止并报告剩余问题
```

## 2. 实施任务

| ID | 工作 | 交付（拟） | 验收重点 |
|---|---|---|---|
| S09-A | 任务板和提案合同 | tasks/proposals、共享事件视图 | 稳定任务键、重复/相似提案规则 |
| S09-B | 原子认领和续租 | CAS/租约、claim 记录 | 同一 Task 一个有效 owner，过期先对账 |
| S09-C | 参与 Agent 决策循环 | propose/claim/help/submit/review | 只从已授权发布能力中加入，参与变化进 manifest |
| S09-D | 工件和合并 | 不可变产物、expected_version、reducer | 并发冲突不覆盖，保留来源与版本 |
| S09-E | 审阅和收敛 | coverage/review/conflict/idle policy | 自评不算独立审阅，投票不自动代表事实正确 |
| S09-F | 硬限制和停止 | 任务/提案/并发/费用/deadline | 超限停止新领取，排空/取消并对账 |

共享状态通过意图和事务变更，不暴露任意可写 Python dict。需要冗余验证时创建两个显式 Task，不能放开单 Task 双重领取。远端参与者仍经 A2A Adapter，不能绕过 Runtime 直接扩张同伴和预算。

## 3. 验收与回滚

并发提交相同任务、双重认领、租约过期、重复工件事件、两个合并者竞争、参与者离线、相互否定和无进展分别测试。检查真实 operation ledger，不能只数收到多少消息。完成条件要求必需主题覆盖、合同通过、所需交叉审阅成立、无活动/待对账任务；到达预算或轮次上限是 partial/failed，不能叫达成共识。

用同输入和总预算比较单 Agent、Supervisor 与 Swarm；只有输出质量/成本证据支持时才启用为业务默认。回滚停止新提案/认领并处理在途任务；改用其他模式创建有明确关联的新 Run，不改写原 Run 的模式和历史。

## 4. 重要文档与交接

本文补齐任务板对象、认领时序、提案去重/合并规则、可计算的完成条件、竞争和空转实验、质量成本比较及默认启用范围。S10 消费稳定的任务板/事件接口，不能用 UI 隐藏未解决冲突。当前实现/评测：**not_run**。
