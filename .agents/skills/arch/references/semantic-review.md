# 语义审阅清单

按任务相关性检查，不能把每条都变成机械审批。

- 现状：主要节点/调用边、状态存放、顺序或并发、是否有消费者均可追溯；旁路、不接入、空实现和模拟数据没有包装成已集成能力。
- 目标：需求有模块/契约/阶段/验收落点，逻辑层、代码包、部署和角色区分；每层写清自身事实及禁止反向侵入的职责。
- 业务：关键路径有输入、参与者、控制权、状态、副作用、产物和接受者；相关失败、等待、取消、重试/恢复和循环停止可解释。
- 协议：规范/线协议/SDK 分别固定；发现、鉴权、调用、状态/ID、流、未知结果与取消不是一个成功 HTTP 示例就代替全部验收。
- Agent：四种协作模式按决策和控制流区别；Handoff 单 owner，Swarm 有认领/去重/收敛；多个策略不并行写同一执行事实。
- 工程：依赖先后合理，每阶段可运行；每步有重要文档、范围、验证和回滚；不把目录搬迁当成业务迁移。
- 版本：候选/锁/实装/兼容/真实调用分别留证，beta API 与稳定包分开；“最新”有本次官方出处和日期。
- 图文：边语义、分组、文字、顺序与源码/契约一致；语法渲染、视觉可读和业务正确分别检查。
- 交付：同一候选 hash，保留用户原改动和历史证据；未运行/未知/未接受明确，机械检查不替代本清单，也不签发用户验收。
