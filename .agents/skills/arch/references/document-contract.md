# 共用文档合同

## 事实与元信息

文档写明目标、日期/时区、状态、适用范围和输入基线。源码基线含 repo/HEAD/dirty 与所选文件 hash 或精确源码定位；没有 Git 也能分析，但写明 unavailable，不能伪造 commit。目录内已有的旧文档只有重新核对后才成为当前事实依据。

把源码事实、静态推断、拟建决定和 UNKNOWN 分开。现状调用/状态回到文件与符号/行号，目标方案回到用户需求和设计取舍。代码示例、表名、配置和部署图若未实现明确为 proposed/example；不要依标题或图的完成感把它们写成已存在。

## 模块文档的共同要求

按适用性表达：目的/边界，输入与消费者，职责/所有权，接口/数据/状态，正常与失败路径，替代方案/代价，迁移/兼容，验收/未验证项。模板标题服务于内容，短模块可合并，确实不适用的项写理由，不填空泛段落。

任何重要阶段都配一篇能独立评审的文档，包含目标变化、方案取舍、精确范围、接口、验证、回滚和结论。总览链接下级，避免跨层重复维护相同细节。使用相对文件链接，引用的候选和证据要可回读；图源与图片一起保留时说明渲染/视觉回读结果。

## 执行与证明

依赖声明、锁、已安装包、import、fake 行为、本地真实协议、真实外部调用和生产结果是不同事实。列实际命令/退出、环境、输入输出/原始脱敏回执与限制。测试数不能证明需求覆盖；hash/链接/语法通过也不能证明语义正确。

步骤常用状态 planned → implementing → verifying → completed；失败仍可继续调查，blocked 需说明实际依赖和解除条件。文档 draft/reviewed 与实现/运行/业务接受分别记录；completed 以本步必要交付为准，不等于用户正式验收。

## 私密配置与记录

不把密钥、完整环境、鉴权头或原始隐含推理复制到文档和快照。敏感配置先确认 Git 跟踪/忽略与实际加载优先级，再在任务授权内处理；文件叫 .env 不代表未受控。只记录配置字段、密钥引用和 provider 非敏感身份。脚本只对允许的文件计算指纹，不归档其原文。

## 输出最小合同

子技能返回：产物路径、来源/候选、当前状态、实际验证、未解决项/限制、下一消费者。无需为了满足模板创建空目录、空角色或无意义的长报告。真实写集只覆盖当前任务，用户已有改动保留。
