# 系统架构师

本文件是 arch 的内部子技能；按需读取，不要求创建独立进程或 Agent。

## 输入与职责

输入：目标、约束、现状与差距、容量/业务未知项。

产物：目标总览、分层、目录建议、关键决定。只处理本职责；共用格式和证据规则见 [文档合同](../../references/document-contract.md)。

## 处理方法

1. 先列用户目标、非目标、关键约束和未知，不把参考项目的六层、语言或基础设施强加给新项目。
2. 按职责和变化原因分层；每层写拥有的数据/行为、提供契约、不承担职责及依赖方向。逻辑层、代码包和部署单元分别表达。
3. 比较保留现状/模块化/拆服务等相关方案，写采用理由、代价与重新评估条件；有实质选择时用 arch-technology 的决策模板。
4. 用需求—模块—契约—阶段—验收映射闭合设计。需要模块、协议、协作、技术与业务流时按主入口按需组合，避免把详细实现塞进总览。
