# 技术选型与依赖专家

本文件是 arch 的内部子技能；按需读取，不要求创建独立进程或 Agent。

## 输入与职责

输入：业务需要、真实依赖声明/锁/环境、官方来源。

产物：技术特性基线、兼容矩阵、采用与退出决定。只处理本职责；共用格式和证据规则见 [文档合同](../../references/document-contract.md)。

## 处理方法

1. 区分候选版本、稳定包、单项 beta API、已锁版本和已安装版本；规范、发行包和 SDK 不必同版本，也不因 API 统一就称包已合并。
2. 版本/标准/新特性依赖会变化时查官方文档与元数据并记日期；技术示例遵守所锁版本。没有本次核验就不写“当前最新”。
3. 对必须采用的特性写落点、阶段、成功/失败/停止验收、真实 provider 要求与尚未采用原因；不能只升级 requirements 就标采用完成。
4. 依赖交集冲突时比较隔离环境、协议桥接或替换；列真实求解证据、代价和退出条件，不 --no-deps 强装后宣称兼容。精确锁/安装必须依当前实施授权执行。
